# 105 — Le `curl` du pack lit la configuration qu'une session écrit

**What to build:** Qu'aucun `curl` que le pack lance n'obéisse à une configuration qu'une session a pu écrire, ou que chacun dise ce qu'il en lit. Aujourd'hui `curl` est lancé nu — sans `-q`, et depuis le shell qui tient les canaux du pack — donc il lit `~/.curlrc` (et ses voisins : `$XDG_CONFIG_HOME/curlrc`, `$CURL_HOME/.curlrc`), qu'une session écrit puisque `claude` tourne avec le `HOME` de l'opérateur ; et une ligne de cette config ajoute à l'appel du pack une URL et une sortie du choix de la session.

**Blocked by:** None

**Write-surface:** `.claude/lib/proc.sh`, `.claude/lib/budget.sh`, `.claude/lib/forge.sh`, `.claude/lib/gate.sh`, `.claude/lib/receipt.sh`, `test/proc.bats`, `test/budget.bats`, `test/tracker-remote.bats`, `test/gate.bats`, `test/canary.bats`, `test/mutate.sh`, `docs/frontiere-de-confiance.md`

**Status:** needs-triage

- [ ] **Le cas mesuré dans le vrai pack ne forge plus rien** (`../sondes/ticket-98/f4-le-curlrc.bats`, C1) : sur le backend `github`, la session écrit `~/.curlrc` (`url = "file://…/forged.txt"` + `output = "/dev/fd/5"`) et le `curl` que l'itération lance pour l'adaptateur écrit **quatre lignes forgées dans le reçu d'audit** — la description de la requête sur la forge —, run `rc=0`, ticket `resolved`, aucune ligne pour le dire. Témoin appairé C0 (la même nuit sans `~/.curlrc`) : aucune.
- [ ] **Les trois effets mesurés sur le vrai `curl`** (8.7.1, darwin, hors du pack : `../sondes/ticket-98/README.md`) sont fermés, ou chacun est écrit avec ce qui le tient :
  - **(a) écrire dans un descripteur hérité en écriture** — `output = "/dev/fd/N"` sur une URL que la config ajoute, **même quand la ligne de commande a son propre `-o`**. Atteint : le reçu ([96], fd 5, l'itération l'a ouvert quand elle appelle l'adaptateur pour marquer, lire un champ ou émettre le reçu), les notes du gate ([94], fd 9) dès qu'une branche lit le tracker distant, et le bout écrivain du canal du slot que [98] fera tenir à l'itération **pendant toute sa vie** ;
  - **(b) ajouter un corps au stdout que le pack lit** — `url = "file://…"` sans `output` : le corps forgé arrive dans `$(curl …)`, même quand la vraie requête a échoué (mesuré `rc=7`, corps présent). Atteint : la réponse de l'**endpoint d'usage**, dans le pilote, sur **tous** les backends (`USAGE_URL` est livré) — c'est la mesure que le pack oppose au `rate_limit_event` qu'une session écrit dans son flux ([08] : « le pilote redemande l'endpoint ») —, et les réponses de la forge ;
  - **(c) vider un bout lecteur** — `data-binary = "@/dev/fd/N"` : le pilote ne relit plus rien. Atteint après [98] : à `MAX_PARALLEL≥2`, le pilote lance `curl` (usage, et sur backend distant le claim, le listing, le balayage des claims) en tenant le bout lecteur de chaque itération en vol — la réponse d'une sœur disparaît, `iteration-lost`. Un déni, pas une forge.
  - Et ce qui ne marche pas, à garder : un bout **lecteur** ne s'écrit pas sur darwin (`output = "/dev/fd/<lecteur>"` → `curl: (23)`). Sous Linux `/dev/fd/N` est `/proc/self/fd/N`, qui rouvre **par chemin** avec le mode demandé — non mesuré, et c'est la borne déjà écrite des trois canaux.
- [ ] **La sortie est instruite et mesurée**, et elle a deux moitiés indépendantes :
  - les descripteurs, (a) et (c) : la forme de `proc_git` ([104]) — sous-shell, 3 à 255 fermés, `exec curl` — ne coûte rien à l'opérateur ;
  - la config, (b) : seule une config non lue la ferme. Mesuré : `-q` **en premier argument** neutralise tout. Le prix est le `~/.curlrc` **de l'opérateur** (proxy, CA, `--resolve`, `--netrc`) ; à trancher et à écrire comme [102] a écrit le prix de `pre-push` — ou une autre forme (config explicite par `-K`, variables d'environnement de proxy laissées à curl) à mesurer.
  - Recensement dérivé, comme celui de [104] : tout `curl` du pack passe par la fonction, et un `curl` nu en position de commande rougit un test.
- [ ] **La phrase du reçu qui dit le contraire est corrigée** (`receipt_render`, « Assembled nowhere a name reaches … every program this run launched without having written it … was started holding nothing but its stdin, stdout and stderr ») : fausse sur un backend distant, mesuré.
- [ ] La ligne du tableau est écrite. Ce que `~/.curlrc` achète n'est pas « faire une requête » — la session le peut déjà — mais **être le `curl` du pack** : à l'instant que le pack a choisi, avec ses descripteurs, et dans la sortie qu'il parse.
- [ ] Témoin appairé ; le canari reçoit le cas qui décide (un reçu distant sans ligne forgée par `~/.curlrc`) ; une entrée de mutation par garantie.

## Comments

- **Ouvert le 07/10/2026 en commençant [98]**, par la question 5 de la DoD posée au mécanisme que [98] devait reprendre : le pilote va tenir des bouts lecteurs et chaque itération un bout écrivain pendant toute sa vie — qu'est-ce que le pack lance pendant ce temps, et qu'est-ce qui le configure ? **File revalidée par Philippe le même jour : [105] → [98] → [99] → [100]**, arête **105 → 98** — sans ce ticket, la ligne du tableau de [98] s'écrirait avec un aveu que [105] réécrirait ensuite, et la forme de [101]–[104] (fermer avant de construire dessus) est la même.

- **C'était écrit comme non examiné.** [104] a laissé, dans ce qu'il n'a pas regardé : « un autre programme du pack qui lirait une config écrivable par une session pour lancer autre chose (`curl` / `~/.curlrc`) ». La réponse est plus large que « lancer autre chose » : `curl` n'a besoin de rien lancer, il **écrit lui-même** là où sa config lui dit, avec les descripteurs de qui l'a lancé.

- **Seul programme de la liste qui lise une config utilisateur** (`gate_path_programs`, recensée par [91]) : `git` passe par `proc_git` ([104]) ; `claude` et `lsof` par `proc_exec_bare` ([101], [103]) ; `at` et `systemd-run` font tourner le job hors de l'arbre de process du run ; `bash -c` ne lit que `BASH_ENV`, une variable de l'environnement du pack ; `awk`, `sed`, `grep`, `sort`, `ps`, `find`, `ls`… n'en lisent aucune. Les **variables** que `curl` consulte (`CURL_HOME`, `XDG_CONFIG_HOME`, `*_proxy`) viennent de l'environnement du pack ; ce sont les **fichiers** qu'une session écrit.

- **Les appels, par shell** (lecture du code, au 07/10) : `budget__request` (deux `curl`, dans le pilote via `budget_check`, cache de 180 s) ; `forge__http` (un `set -- curl …` puis `"$@"`), appelé par les deux adaptateurs distants dans le pilote (claim, listing de frontière, balayage de liveness, réinjection) **et** dans l'itération (`tracker_field`, `tracker_mark_resolved`, `tracker_snapshot`, `tracker_unclaim`, la politique d'échec, `forge_emit_receipt`) — le reçu ouvert à la ligne `receipt_open` de `loop__iterate` et fermé à `receipt_close`, donc ouvert pendant tous ceux-là. À `MAX_PARALLEL=1`, `budget_check` n'est atteint qu'une fois rien en vol (le plafond renvoie à `loop__reap 1` avant) : le pilote n'y tient alors aucun bout lecteur ; au-dessus, si.

- **Ce que ce ticket ne règle pas et qui n'est pas à lui** : sur un backend distant, une session écrit déjà le tracker par le réseau (ligne « Ce qu'une session écrit dans le tracker d'un backend distant ») — forger une *réponse* de la forge par `~/.curlrc` n'y ajoute pas une classe, seulement un chemin. Ce qui est neuf est le **reçu** (un document que le pack signe) et l'**usage** (la mesure que le pack oppose au flux).
