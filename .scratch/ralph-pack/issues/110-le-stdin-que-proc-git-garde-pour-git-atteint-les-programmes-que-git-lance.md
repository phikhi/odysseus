# 110 — Le stdin que `proc_git` garde pour git atteint les programmes que git lance

**What to build:** Qu'un programme que git lance **pour le pack** (un `core.fsmonitor`, un hook configuré, un filtre `clean`/`smudge`) ne reçoive pas le stdin de l'appelant — ou que chaque appelant qui ne pipe pas dans git lui donne `/dev/null`. `proc_git` ([104]) ferme 3..255 mais **garde le stdin** (il le doit : `check-ignore --stdin`, `update-index --index-info`, `hash-object --stdin` pipent dedans). Le programme que git lance en hérite ; dans une boucle `while IFS= read -r x; do proc_git <op d'index> …; done <<LIST`, ce stdin est le **reste de LIST**, et le programme peut le vider. C'est le trou stdin de [106], pour git — explicitement laissé à la passe par [106]/[107].

**Blocked by:** None

**Write-surface:** `.claude/lib/proc.sh`, `.claude/lib/gate.sh`, `test/proc.bats`, `test/gate.bats`, `test/mutate.sh`, `docs/frontiere-de-confiance.md`

**Status:** resolved

- [x] Le recensement, dérivé ([91]) et pas listé : quelles boucles `while … read … done <<LIST` (ou here-string) ont dans leur corps un `proc_git` sur une **op d'index** (`add`, `update-index`, `checkout-index`, `reset`, `status`, `write-tree`) — les seules où git interroge `core.fsmonitor`/les hooks/les filtres. Foyers lus en ouvrant : `gate.sh` `<<FORCED` (force-staging des chemins gardés), `<<CHANGED`, `<<PATHS`, `<<ROLLBACK`, `<<RESTORE`.
- [x] La forme de la réparation et son prix : un appelant qui **ne pipe pas** dans git doit lui donner `</dev/null` (la forme que `proc_group_fork` donne à `TEST_CMD`) ; le seul qui pipe (`gate_newly_hidden` : `printf … | proc_git check-ignore --stdin`, `gate.sh:2857`) ne peut pas — là git ET le programme lancé lisent le **même** tuyau et se le disputent, c'est un autre cas, à dire. `proc_git` ne peut pas fermer son propre stdin (des appelants le remplissent) : la discipline est **par appelant**, ou une variante de `proc_git` qui annule stdin pour qui ne pipe pas.
- [x] La garantie de [104] remise d'accord avec ce qui est vrai : son commentaire dit « nothing a program git starts could inherit, whatever named it, at any MAX_PARALLEL » — **faux de fd 0**. Le commentaire de `proc_git` dit « stdin, stdout and stderr are the caller's » : vrai de git, le trou est que le programme que git **lance** en hérite aussi.
- [x] Témoin appairé, une entrée de mutation par garantie, la ligne du tableau (ligne 49, `proc_git`) corrigée : ce qu'elle tient au-dessus de stderr, et ce qu'elle **ne** tient **pas** en-dessous (fd 0 pour le programme lancé).
