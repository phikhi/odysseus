# Carte : Framework de développement réutilisable (blueprint)

Label: wayfinder:map

## Destination

Blueprint **gelé** d'un framework de dev réutilisable, posé sur les skills Matt Pocock déjà installés. Ajoute (a) une **ralph loop bash** relançant une session Claude headless à contexte frais par tâche — jamais compacté, garanti « smart zone » <200K ; (b) la **gestion du budget d'usage** 5h/hebdo dans la boucle (pause/reprise) ; (c) le chaînage discovery→delivery réutilisant l'existant. Décisions verrouillées → construction mécanique. **Zéro code produit ici.**

**Durcissement v2 (2026-07-24) :** le blueprint est **rouvert** pour intégrer 11 leçons du workflow Multiplyz (`ANALYSE-multiplyz-vs-odysseus.md`) — apprentissage durable, gate de valeur bout-en-bout, vérif visuelle, axe fidélité, parallélisme worktrees, backend tracker GitHub/GitLab, successeur one-shot, reçu d'audit, scope-guard, ADR en delivery, verrou fin. Toujours **plan-don't-do** : ces tickets tranchent des **décisions**, aucun code produit.

## Notes

- **Domaine** : orchestration Claude Code (skills, subagents, hooks, slash-commands, CLI headless).
- **Substrat** : réutilise `grilling`, `research`, `domain-modeling`, `to-spec`, `to-tickets`, `implement`, `tdd`, `code-review`, `triage`, `wayfinder`. On ne les réinvente pas.
- **Contrainte forte — pas de compaction** : la compaction/`handoff` de contexte mène en dumb-zone. Le passage de session = **ralph loop bash** qui relance `claude` headless avec contexte frais/optimal par tâche. L'état durable vit dans les fichiers du tracker, relu à neuf à chaque itération.
- **Contrainte 200K** : chaque tâche = 1 session fraîche qui doit finir sous 200K.
- **Contrainte usage** : plan Max — fenêtre session 5h + limites hebdo ; la boucle doit détecter la limite, pauser, reprendre.
- **Autonomie** : la boucle broie UNIQUEMENT les tickets de delivery ; discovery reste HITL en amont (spec+tickets validés = contrat exécuté).
- **Skills à consulter chaque session** : `grilling`, `domain-modeling`. `research` pour les tickets `research`.
- **Langue** : répondre en français.
- **Durcissement v2** : source = comparaison avec Multiplyz (`ANALYSE-multiplyz-vs-odysseus.md`). Les tickets [11]→[21] **révisent/étendent** des décisions v1 verrouillées (voir « En révision — durcissement v2 » ci-dessous) ; charter avec ce contexte, ne pas re-trancher le v1 sans raison. **Hors périmètre v2** : réconciliation quota (§5.3, cf. Out of scope).
